# 0022 — Options as a first-class derivative entity (signed mark, intrinsic-only, own store + choke point)

- Status: Accepted
- Date: 2026-06-21
- Deciders: orchestrating agent (autonomous "drive E2E" mandate; user AFK and delegated the call)
- Related: design `docs/rfc/investments/sys-options-data-model.md`; ADR 0020 (bonds first-class, the precedent); ADR 0021 (hybrid IA — Options is sub-tab #5, NEW); `.claude/rfcs/bonds-first-class.md`

## Context

The hybrid IA (ADR 0021) adds an **Options** sub-tab for covered-call writes, cash-secured-put (CSP) cash-locks, and defined-risk long calls/puts — each with a live ITM/OTM badge, a mark value, and a premium/collateral basis, valued in base currency like every other holding. Today none of that is representable: no `option` asset class, no contract metadata, no expiry-aware mark, no signed (asset-or-liability) valuation for a holding.

The first instinct is to reuse the existing instrument/position/lot spine the way bonds did. ADR 0020 put `BondTerms` on the **instrument** (`backend/models/instrument.py`) and reused `Position` for the holding precisely because a bond *is* a single-valued thing you own a quantity of — its whole elegance was "no new formula, `qty × price × quote_per_unit` already produces the right number" (`positions_service.hydrated()`, `backend/services/positions.py`). An option fails every premise of that reuse (`docs/rfc/investments/sys-options-data-model.md` §Problem):

1. **It expires** to exactly 0 (or is exercised/assigned) — a hard cliff, not a bond's accretion ramp.
2. **It can be a liability.** A *short* call/put (the income leg of a covered call / CSP) is a written obligation: positive premium received up front, **negative** mark thereafter. A `Position` is always asset-side, and `apply_position_change` refuses a second active *liquid* position and assumes `qty > 0` is held value.
3. **Its value derives from another instrument.** Mark and moneyness are functions of the **underlying's** live price vs `strike`; there is no Yahoo quote for a specific OCC contract, and we are deliberately NOT pulling an options-chain/IV feed.
4. **It carries a `×100` multiplier and a call/put × long/short cross-product** the flat `quantity` field cannot express.

Forcing options onto `Position` would mean special-casing the duplicate-position guard, the `qty > 0` display filter, the lots/realized spine, and — most consequentially — the **asset-only net-worth fold**, which has never had to sum a holding on the liability side. That is a worse outcome than the path bonds got to avoid. The fork must be settled before the Options sub-tab, its lens, and the net-worth banding can be built.

## Decision

Options become a **dedicated first-class derivative entity** with its own store and choke point — NOT overloaded onto `Position`.

1. **Dedicated `OptionContract` entity + store** (`backend/models/option.py`, `backend/db/option_contract_store.py` — `OptionContractStore`, a `JsonStore` subclass, factory `_make_option_contract` as the single coercion authority). This mirrors how equity comp got `grants.json`/`GrantStore` rather than overloading positions, not how bonds reused `Position`. The contract still *references* a real underlying via `underlying_instrument_id`, so look-through, live underlying price, and sector classification all reuse the existing instrument master — but the option holding is its own record. Checkpoint-INCLUDED (it is portfolio truth, like lots/grants).

2. **A signed mark makes short/written contracts a net-worth *liability*.** The `side` field is the asset/liability switch: `long` → asset (premium paid, mark ≥ 0); `short` → liability (premium received, mark ≤ 0 — a written ITM option is money owed). `mark_value_base` returns `+value` for longs and `−value` for shorts. Net worth folds it on the correct side: `ledger._MARKET_BAND` / `portfolio_history._ASSET_CLASS_TO_BAND` gain an `option → "option"` mapping and the band sums **signed** marks. This is genuinely new behavior — the existing fold has only ever summed asset-side holdings — and is the load-bearing reason an option cannot be a single-valued `Position`.

3. **Intrinsic-value-from-underlying marks — no IV / options-chain feed.** `mark_value_base` (in `backend/services/options.py`) uses **intrinsic value only** in v1: `intrinsic_per_share × contracts × multiplier`, signed by side, derived from the underlying instrument's already-resolved price vs `strike`. There is NO new external fetcher — options ride the underlying's existing quote via the `prices` map / `positions_service._resolve_price` (lazy-imported to dodge the positions⇄options cycle, the `services/fixed_income.py` `summary` pattern). This is the honest analog of computed-mark bonds having no live secondary quote: deterministic, underlying-derived, always fresh, with the missing time/extrinsic value a documented v1 limitation. An optional broker/MCP-supplied `mark_override` (IBKR) may out-rank intrinsic when present — same precedence as a live price out-ranking a computed one.

4. **`options_service.apply_option_change(change)` choke point + premium-leg `external_id` idempotency.** A single write entrypoint (the `apply_lot_change` / `apply_position_change` / `apply_equity_change` convention) handling `{open, close, expire, update, delete}`, shared by REST and AI apply tools so every write funnels through `JsonStore._save_raw → core.io.fire_write_hook` and is checkpoint-covered. Writes are **idempotent on `idempotency_key`** (the broker order id) and an identical-open-signature **double-book guard** refuses a manual + sync double-entry. Opening a contract does **not** auto-book the premium cash; the actual premium flows through the **existing** `ledger_service.create_transaction` choke point only when the caller supplies a `premium_account_id` (the `_maybe_deposit_proceeds` bridge in `backend/services/lots.py`), FX-converted with a deterministic `external_id` and checkpoint-covered. No silent premium or collateral movement — money movement always confirms (the bonds-coupon posture).

5. **Scope = covered-call / CSP overlays + defined-risk longs. Greeks / margin / rolling / assignment DEFERRED.** Moneyness is DERIVED (never stored); a daily deterministic `option_expiry_sweep` task (the `vest_reminder` precedent) flips `open → expired` at the cliff — an OTM expiry books 0 residual, while an ITM expiry is flagged for manual assignment/exercise (automation deferred). CSP collateral is a reference figure surfaced as "encumbered cash" — the cash is **not** moved. A covered call's collateral points at the securities account; the lens flags an uncovered/naked write rather than silently accepting it. Multi-leg spreads are a `strategy_tag` label only.

A lightweight `AssetClass.option` is added as an additive enum value (`backend/models/instrument.py::AssetClass`, `backend/db/instrument_store.py::ASSET_CLASSES`) purely so net-worth/allocation banding and `xray` classification recognise the derivative band — the contract store, not an instrument of that class, remains the source of truth.

## Consequences

- **Positive:** the four `Position`-breaking properties (expiry-to-zero, liability side, underlying-derived mark, side+multiplier cross-product) are each modelled directly instead of special-cased; the net-worth fold learns to sum a signed liability holding *once*, cleanly; no migration (net-new store + additive default-absent enum, the bonds pattern); the entity rides the existing instrument master for look-through and pricing, adding zero contract-level network calls.
- **Cost:** a net-new entity end-to-end (model + store + service + 5 endpoints under `backend/api/options.py` + ~6 AI tools in `backend/ai/tools/options.py` + banding wiring + expiry-sweep task + full test matrix) — XL effort, the Options sub-tab's critical path. The signed-valuation + expiry-cliff math is the most bug-prone surface, guarded by load-bearing short-contract and expiry regression tests.
- **Documented limitation (intentional):** intrinsic-only marks understate a long's true (extrinsic) value and a short's true cost while OTM. Accepted as the honest v1 analog of computed-mark bonds; revisited via the optional broker `mark_override`.
- **Deferred (recorded):** Greeks, margin modelling, rolling, assignment/exercise automation, and multi-leg leg-linking are out of v1 scope; ITM-expiry assignment is flagged for manual handling, a guided "record assignment" is a fast-follow.
- **Surfaces touched:** CLAUDE.md "write choke points" list gains the `apply_option_change` row; `backend/core/portable.py` export manifest gains `option_contracts.json` (portfolio truth, portable); frontend `constants.ts` gains the `option` color/label/order. Excluded from TWR/MWR in v1 (performance analytics is a later tier, exactly as bonds were).

## Alternatives considered

- **Overload options onto the `Position` spine (the bonds path).** Rejected: an option fails all four premises that made the bonds reuse elegant — it would require special-casing the duplicate-position guard, the `qty > 0` filter, the lots/realized spine, and (worst) teaching the asset-only net-worth fold to go negative inline. A dedicated entity is strictly cleaner, exactly as equity comp chose `grants.json` over positions.
- **Pull a live options-chain / IV feed for true marks (with Greeks).** Rejected for v1: adds a contract-level network dependency and a whole pricing surface for a covered-call/CSP overlay use case; intrinsic-from-underlying is deterministic, always fresh, and free, with the time-value gap a documented limitation and a broker `mark_override` escape hatch.
- **Auto-book the premium cash / move CSP collateral on open.** Rejected: violates the "money movement always confirms" posture (ADR 0020's coupon decision). Premium rides the existing ledger choke point on confirmation; collateral is surfaced as encumbered, never silently transferred.
- **A band-only constant instead of `AssetClass.option`.** Rejected as the cleaner classification hook; the enum value is additive/no-migration either way, and the contract store stays the holding source of truth regardless.
