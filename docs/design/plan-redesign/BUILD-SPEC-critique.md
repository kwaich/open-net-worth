## Adversarial Review — Projections & Retirement Redesign Spec

### 1. DATA REALITY (READY claims vs actual endpoints)

- **[BLOCKER] `fPct` double-percent + wrong `fraction` flag throughout.** `success_probability` is a 0–1 fraction (confirmed in `montecarlo.py` and `RetirementReadiness.verdict`). The spec repeatedly writes `fPct(mc.success_probability, {fraction: false}) + '%'` (R0 hero, readiness cards, A/B `moneyLasts`, P2 success card). `fPct` (format.ts:215) ALREADY appends `%`, and `{fraction:false}` treats the input as an already-multiplied percent. So `fPct(0.82, {fraction:false}) + '%'` → `"0.82%%"` — wrong value AND doubled sign. **Fix:** use `fPct(p, {fraction: true})` with NO trailing `'%'` everywhere a 0–1 probability is rendered. The Projections hero stat 3 (`fPct(success_probability, {fraction: true}) + " lasts"`) is the only one that's correct.

- **[BLOCKER] `scorecard.projected_monthly_net` does not exist as a nested field.** §3a P1 footnote and §5 reference `scorecard.projected_monthly_net`. There is no `scorecard` wrapper. **Fix:** read `data.projected_monthly_net`; also `data.periods` not `scorecard.periods`.

- **[MAJOR] `ForecastScorecard` type is already exported** — §1 "Files modified / `api/insights.ts` — Export `ForecastScorecard` type" is a no-op; it's already exported (insights.ts:39).
