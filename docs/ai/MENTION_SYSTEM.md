# Lucius mention system (`@` entities/agents · `/` verbs)

> **On-demand reference.** Not loaded into every turn — read it when you touch this area.
> Decisions and their reasoning live in [`docs/adr/`](../adr/); this file states current truth.

Pull-based, registry-driven, multi-agent-ready (design `docs/superpowers/specs/2026-06-24-lucius-mention-system-design.md`; ADR 0026; rollout P0–P4 SHIPPED). Generalizes the S1 push-`✦` resolver. **Surfaced everywhere via the floating dock** (ADR 0028; plan `docs/superpowers/plans/2026-06-25-ask-lucius-everywhere.md`; acceptance `docs/qa/acceptance/ask-lucius-dock.md`): an always-on `LuciusDock` (collapsed pill ↔ expanded composer card, bottom-right, mounted once in `RouterShell`) that expands into the re-skinned `.lx-side` `ChatPanel`, both sharing ONE chat via `state/luciusChat.tsx` (`useLuciusChat`). The dock + side panel share `components/chat/lucius/` (`Composer` wraps the contenteditable `MentionComposer`; `Autocomplete` grouped picker; `ScreenContextBar`; `Chip`/`MentionDetail`/`CitationChips`) + `lucius/identity.tsx`. Re-skin only — POC plumbing (streaming, tool-calls, `ChangePreview`, artifacts) is KEPT.
- **Server-authoritative registry** — `services/mentions/` package: `types.py` (`MentionProvider`/`SearchQuery`/`ICONS` leaf — breaks the registry↔providers cycle), `registry.py` (`REGISTRY`: `type`, `surfaces ⊆ {entity,agent,verb}`, `icon`, `resolve`, `search`), `descriptor.py` (`EntityDescriptor` — the single declarative description of a mentionable type, RFC `2026-06-25-lucius-generic-entity-registry` §4.1), `_collect.py` (the auto-collect seam for descriptor registrations — mirrors the `@tool` registry convention: a descriptor module calls `register(d)`, nothing hand-lists them), `descriptors/` (one module per type or type family — `connector.py`/`equity_lots.py`/`financials.py`/`multi_surface.py`/`new_types.py`/`report.py`/`singletons.py`/`store_backed.py`), `generic.py` (generic search+resolve DERIVED from an `EntityDescriptor`, §5 of the same RFC — most types need no bespoke resolver), `labels.py` (`(type, id) → MentionRow`, resolved server-side — the gap nothing else in this system closes: turning a bare id back into a labelled chip), `resolve.py` (per-type resolvers for the types that still need bespoke logic — fresh, bounded, base-correct, graceful `not_found`), `search.py` (fan-out filtered by `provider.surfaces & query.surfaces`, rank `exact>prefix>substring`, opaque-offset cursor; **in-memory scan, no index**), `providers.py` (`search_<type>`), `_common.py` (shared helpers, e.g. `_TYPE_SYNONYMS`), `dispatch.py` (`resolve_mentions`/`format_mention_context` route through `REGISTRY`; `KNOWN_TYPES = frozenset(REGISTRY)`). **25 types** (re-verified against the live `KNOWN_TYPES` registry, now built from `EntityDescriptor` registrations under `services/mentions/descriptors/`, not hand-listed in `registry.py`): account, alert, allocation_slice, automation, budget_month, category, commitment, connector, disposal, envelope, grant, holding, income, instrument, lot, net_worth, notification, payee, report, returns, skill, target, transaction, vest, watchlist. **`rule`/`scheduled_task`/`agent` are RETIRED** — folded into the single `automation` type when the standalone Rules engine, the Agent product, and Scheduling were unified into Automations (2026-08-02, `d0da1a09`; see `docs/ai/TOOL_CATALOG.md`'s "Automations" entry). **`intel_signal` was RENAMED `notification`** (2026-08-20, revision 0044) — it is backed by `NotificationLogStore`/`notification_log` (the titled in-app notification feed: id/title/summary/severity/type), NOT `IntelSignalsStore`/`intel_signals.json` (per-ticker signal state, not a discrete mentionable event) — the old name was a pre-rename misnomer even before this doc's list caught up. `disposal` is a genuinely new type not previously listed here. **The surface decides the mention type** (ADR `2026-07-11-envelope-first-class-mention-type`): every Plan budget row drags/harvests as `envelope:<envelope id>` (zero-category pots included); Manage-categories rows drag as `category:<category id>`; the `category` type covers ALL kinds — a category with no budget row (income/transfer/investment, unlinked expense) search-lists and resolves via a category-store fallback (`budgeted=False`) instead of `not_found`.
- **Row contract** `MentionRow = {type, id, label, sublabel, value, icon, surface}` + optional `color` (the entity's own display color — account tint, envelope/category dot; also rides `data-entity-color` on DOM-harvested rows, `isSafeCssColor`-validated client-side before any render, ANY type not just account) — **`value` == the resolver's `ref`** (== id for stored rows; a synthesized selector for singletons/slices/periods: net_worth→"", allocation_slice→"asset_class:equity", returns→"1Y"). Client stays **type-agnostic** (renders any row by its self-describing fields + `surface`); the only per-type client knowledge is the icon glyph.
- **Endpoint** `GET /api/mentionables?q=&types=&surface=&limit=&cursor=` → `{items, next_cursor}` (`api/mentionables.py`, thin, auth-gated). `surface` (CSV) selects providers — the `@` picker requests `entity,agent`; `/` requests `verb`. **CORRECTION: the `agent` surface is now dead** — no descriptor under `services/mentions/descriptors/` declares `surfaces` including `"agent"` any more (the default, `EntityDescriptor.surfaces`, is `frozenset({"entity"})`); only the `skill` provider still serves both `entity`/`verb`. This is a consequence of the Agent product's retirement below, not a separate change.
- **Turn contract** (`ChatRequest`): `mentions[]` (entity context, multi-select, resolved server-side onto the user turn — S1 spine) + `responding_agent` (see the RETIRED-feature note in `docs/ai/TOOL_CONVENTIONS.md`'s "Per-turn tool PERMISSIONS" section — the field still exists on the request model and the frontend still sends it, but `api/chat.py` no longer reads it; it is a dead no-op) + `skill` (the immutable `/` verb id, structured; preferred over leading `/slug` text detection and resolved by `resolve_slash_skills` into a host-owned direct invocation).
- **Frontend** — `hooks/useMentionables.ts` (local DOM harvest of `data-entity-id="{type}:{value}"` + `data-entity-label`, instant, re-harvested on the `lx-rescan` event so a tab switch never leaves stale "on screen" rows behind; 150ms-debounced backend merge w/ AbortController cancel + dedupe by `(type,value)`; surfaces an `error` + `retry()` for the picker error row — **no client-side "recently used" cache**, removed 2026-08-11: a picked mention's `localStorage` entry had no connection to server-side deletion, so a since-deleted/merged-away entity kept resurfacing forever, selectable, in every search matching its stale cached label) + `components/chat/lucius/Autocomplete.tsx` (grouped: Screen context → On this screen → Deeper sources → Talk-to (`--lucius`) → entity types → Everywhere/remote; keyboard-first; `loading`/`error+Retry`/`empty` states) inside `lucius/Composer` (shared by the dock + side panel). Pick by `surface`: entity → `chatComposer.addMention` chip; agent → `setRespondingAgent` (single-select, "To ·" recipient — CLIENT CODE ONLY now, see the dead-field note above: nothing populates the `agent` surface to pick FROM any more, and the backend ignores the value); verb → `setPendingSkill`. Rows opt in via `utils/mentionable.entityRefProps(type,value,label)`. `@`/`/` triggers require a word boundary (`detectAtToken`/`detectSlashToken`); old `MentionPicker`/`SlashCommandPopover` superseded. **Type-synonym search** ("stocks"→holding…): `services/mentions/_common._TYPE_SYNONYMS` (moved out of `providers.py` at some point after this doc was written) — the `"agents"→agent` entry it used to carry is gone with the `agent` type.
- **Screen awareness** (ADR 0028; supersedes ADR 0027 §1) — markup-driven, captured LIVE at send time. `lucius/screenContract.ts` `getScreenSnapshot(visibleIds)` reads a declarative `data-ctx-*` contract off the DOM: `data-ctx-region="content|nav"`, `data-ctx-title`, `data-ctx-fact`, `data-ctx-state`, rows `data-ctx`+`data-entity-id`+`data-ctx-type`+`data-ctx-fields`+`draggable`, modals `role="dialog"`, opt-outs `data-ctx-ignore` / **`data-ctx-secret`** (the latter also hard-excludes the subtree from the whole snapshot). Two-layer body (VISIBLE NOW vs ALSO ON SCREEN) + form-harvest (**credential/secret inputs are NEVER harvested** — `isSecretControl`) + handle manifest. Per-screen hooks (`lucius/useScreenContract.ts`): `useRegisterHandles`/`useRegisterScreenFacts`/`useRegisterScreenPrompts`. Snapshot rides the user turn via `services/screen_context.format_screen_context` (bounded, **fenced as untrusted `«screen»…«/screen»` data, control-char + marker stripped**); deep content is a `ScreenHandle{source}` lazily fetched server-side by the `get_screen_detail` tool (SSRF-guarded URLs; `net_worth_series:`/`holdings:all`/`transactions:…`/`price_series:…` hydrators; per-turn cap 3). Instrumented screens: Cash, Investments, Asset Detail, Overview, Plan, Tax. Right-click "Ask Lucius" + drag-into-dock are global delegated (`components/chat/lucius/dragRightClick.tsx`). **Two-way (ADR 2026-07-11):** screens also register drivable COMMANDS (`useRegisterScreenCommands`; specs + off-screen catalog in `lucius/screenCommands.ts`) advertised on the snapshot (`ScreenSnapshot.commands`, ≤12) and executed by the generic `run_screen_command` tool (ZERO store writes — ephemeral UI state; validated against the turn's stashed manifest; it drives a LIVE BROWSER SESSION, so it is only meaningful on a turn that has one — there is no longer a tier or allowlist excluding it, just nothing for it to drive unattended) → `screen_command` SSE → `lucius/bus.ts` (sticky park/replay; a parked result renders a navigation chip that re-dispatches on click, reload-safe via the rehydrated tool pair). Freshness is the other half: write tools self-declare `mutates=("domain",…)` on `@tool`, the dispatch loop emits ONE deduped `data_changed {domains}` SSE before `turn_done`, and tabs subscribe via `useDataVersion(domain)` — the frontend `MUTATING_TOOLS` list is GONE. **Every registered tool is EXPLICITLY classified** (`tests/test_tool_domains.py`, inverted 2026-07-18 — see the "Tool write classification" section below); the old sweep only policed tools whose NAME started with a write-ish verb, which let read-named writers ship untagged for years. First adopter: Plan/Outlook (`plan.stage_whatif` baseline-relative replace + `plan.reset`; `plan`/`profile` domain refetch + lever re-seed; intent routing in `ai/prompts.py`: "what if…" → stage ephemeral, stated fact / "update my plan" → `update_profile`/`set_plan_baseline` persisted).
- **A registered type must be REACHABLE from the UI, not merely searchable** (2026-08-23) — registering an `EntityDescriptor` buys search+resolve; a row stamping `data-entity-id` (+`draggable`) is what buys right-click "Ask Lucius", drag-into-dock and "on this screen" harvest. `dragRightClick.tsx` binds globally by attribute selector, so a missing attribute fails SILENTLY — nothing throws, the menu just never appears. That gap shipped four times (`automation` 2026-08-11; `commitment`/`skill`/`watchlist` 2026-08-23), so it is now a gate: **`tests/test_mention_type_frontend_coverage.py`** parametrizes over the live `REGISTRY` and fails if any type has no frontend emitter and no reasoned `EXEMPT` entry. The per-component `lucius.entityWiring.test.tsx` files stay the behavioural half (exact attributes); the registry-driven test is the discovery half (did anyone wire it at all). Exempt today: `net_worth`/`returns`/`budget_month`/`report` (derived selectors, no row) and **`target` — savings targets have a complete backend and NO frontend at all**, an unbuilt feature rather than a wiring gap. ADR `2026-08-23-a-registered-mention-type-must-be-reachable-from-the-ui`.
- **KNOWN GAP: `ui/SummaryBar`'s `mention` prop has no callers.** The primitive renders an "Ask Lucius about this" ✦ on a stat card when passed `mention`, and nothing in the app passes it — so no KPI card on Tax, Investments (Options/Equity/Income/Activity), Equity, TaxLossHarvest, RealizedPnl, BondMaturity or CostPanel is mentionable. Left as-is deliberately: which headline figures deserve to be entities is a design question, not a wiring omission.
